# 屏幕控制接口

面板是双稳态的，断电、重启都不会丢画面，所以固件**开机不自动刷屏**：重烧固件、按复位都不会把屏刷一遍。要换画面时用下面三种方式触发。

一次整帧刷新约 35 秒。刷新期间到达的命令会在这一轮结束后合并成一次动作，不会排队连刷。

## 画面来源

优先级：TF 卡根目录的 `.bin` 帧文件 > artifacts 分区里烧进去的开机画面 > 白屏。

帧文件按文件名排序，翻页在这个排序后的列表里循环。

## 按键

| 键 | 引脚 | 动作 |
| --- | --- | --- |
| KEY1 | GPIO3 | 上一张 |
| KEY2 | GPIO8 | 下一张 |
| KEY3 | GPIO18 | 原地重刷当前这张 |

下降沿中断触发，60 ms 时间窗消抖，按住不连发。

## 调试串口

走 USB-SERIAL-JTAG，和日志同一个口，115200。敲单个字符即可，不需要回车：

| 字符 | 动作 |
| --- | --- |
| `r` | 刷新当前这张 |
| `n` | 下一张 |
| `p` | 上一张 |
| `f` | 显示出厂画面（artifacts 分区里那张） |
| `s` | 立即进入深度睡眠 |

其它字符会打印一行用法提示。

## HTTP

设备连上热点后，在同一热点下的电脑上：

```bash
curl http://<设备IP>:8080/display/refresh
curl http://<设备IP>:8080/display/next
curl http://<设备IP>:8080/display/prev
curl http://<设备IP>:8080/display/factory
curl http://<设备IP>:8080/power/sleep
```

返回 `refresh queued` 之类的纯文本表示命令已入队，不代表画面已经换好——刷新本身要几十秒。

设备 IP 见串口日志里 `wifi: 已连上 ...` 那一行。

## 睡眠

设备在电池供电、空闲 30 s 后自动进入深度睡眠，按键或定时器唤醒；插着充电器时不睡，所以接着 USB 调试和 OTA 都不会被打断。`s` 和 `/power/sleep` 可以立即入睡，不看充电器状态。完整规则、唤醒源和电流预算见 [低功耗.md](低功耗.md)。
