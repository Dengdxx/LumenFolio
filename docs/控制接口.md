# 屏幕控制接口

面板是双稳态的，断电、重启都不会丢画面，所以固件**开机不自动刷屏**：重烧固件、按复位都不会把屏刷一遍。要换画面时用下面三种方式触发。

一次整帧刷新约 35 秒。刷新期间到达的命令会在这一轮结束后合并成一次动作，不会排队连刷。

## 画面来源

优先级：TF 卡根目录的 `.bin` 帧文件 > artifacts 分区里烧进去的开机画面 > 白屏。

帧文件按文件名排序，翻页在这个排序后的列表里循环。

局域网传来的那一张不进 TF 卡。它写在 artifacts 分区的上传槽里，覆盖上一张，开机画面不动。设备收到后自动刷上屏。

```powershell
.\app\pc\LumenFolio.exe --host <设备IP> frame 照片.png
```

界面里填同一地址后点「上传到相框」，用的是当前取景和当前抖动算法。直接提交已编码的 EPD1／EPD2 帧时：

```powershell
curl.exe --fail-with-body -H "Content-Type: application/octet-stream" --data-binary "@画面.bin" "http://<设备IP>:8080/frame"
```

`POST /frame` 只接受固定 `Content-Length` 的 `application/octet-stream`，长度须等于整个编码帧的实际字节数且不超过 960012。支持整幅 EPD1 原始帧和 EPD2 zlib 无损压缩帧，布局见 [帧格式与兼容性](preview.md#帧格式与兼容性)；直接上传 `.bin`，不使用 HTTP gzip。

帧头可以跨多次接收，验证尺寸和总长度后才擦除上传槽。先写载荷与其余帧头，最后单独写魔数，未收完的帧不会被识别。202 只表示写入并请求刷新，不表示压缩校验或约 35 秒的刷新已经完成；显示任务在长度、完整流结束与 Adler32 都通过后才绘制，错误帧记录日志而不上屏。

## 浏览板端画面

Windows 和 Android 配套 App 可按来源浏览并预览相框上的画面。浏览、预览和查询容量只读取数据。有效请求处理期间暂停自动深睡，请求结束后重新计时。

| 请求 | 结果 |
| --- | --- |
| `GET /frames?source=artifacts` | 列出 Flash artifacts 分区的有效画面，`boot` 为开机画面，`inbox` 为最近一次上传的画面 |
| `GET /frames?source=sd` | 列出 SD 卡根目录的有效 `.bin` 帧文件，ID 为实际文件名 |
| `GET /frames/storage` | 查询 Flash artifacts 和 SD 的已用字节数及总字节数 |
| `GET /frame?source=<artifacts 或 sd>&id=<画面 ID>` | 返回头部声明长度的 EPD1／EPD2 编码帧，类型为 `application/octet-stream`。画面不存在返回 404 |

列表响应形如 `{"available":true,"frames":[{"id":"boot","name":"开机画面"}]}`。SD 卡已挂载但没有画面时返回 `available:true` 和空数组，未挂载时返回 `available:false` 和空数组。

容量响应形如 `{"artifacts":{"used_bytes":960012,"total_bytes":11927552},"sd":null}`。Flash 已用量是两个有效帧的编码长度之和，总量是整个 artifacts 分区的容量。SD 采用文件系统报告的容量和空闲空间，已用量包含卡上的所有文件。未挂载或无法读取的来源返回 `null`。

### 易错点（务必遵守）

- 文件名包含中文、空格、加号或百分号时，直接拼接 URL 会让服务端读到错误的参数。按 UTF-8 对 `id` 做 URL 百分号编码。SD 列表沿用翻页的根目录扫描范围和最多 32 个文件、文件名最多 95 字节的限制。
- 列表通过帧头筛选并排除截断文件，损坏的压缩数据仍可能出现在列表中。预览端须按帧格式完整解码，再显示画面。

## 按键

| 键 | 引脚 | 动作 |
| --- | --- | --- |
| KEY1 | GPIO3 | 上一张 |
| KEY2 | GPIO8 | 下一张 |
| KEY3 | GPIO18 | 原地重刷当前这张 |

下降沿中断触发，60 ms 时间窗消抖，按住不连发。

## 控制台

串口和 HTTP 用的是同一套命令：语义只有一份实现，回执文本也完全相同。日常操作走 HTTP 就行，串口留着看日志。

| 命令 | 动作 |
| --- | --- |
| `n` / `next` | 下一张 |
| `p` / `prev` | 上一张 |
| `r` / `refresh` | 重刷当前这张 |
| `f` / `factory` | 显示出厂画面（artifacts 分区里那张） |
| `s` / `sleep` | 立即进入深度睡眠 |
| `awake` / `hold` | 本次开机不再自动睡眠，直到复位或 `sleep` |
| `status` | 运行状态与睡眠诊断 |
| `help` / `?` | 命令表 |

**串口**：USB-SERIAL-JTAG，和日志同一个口，115200。按行输入，**回车执行**，支持退格，输入会回显。

**HTTP**：`GET /console?cmd=<命令>`，回执就是纯文本。

```bash
curl 'http://<设备IP>:8080/console?cmd=next'
curl 'http://<设备IP>:8080/console?cmd=status'
```

`status` 的输出形如：

```
wake=cold display=idle last=ok frames=1 idx=0 plugged=0 usb=1 idle=4200ms sleep=off-powered
battery=3828mV 64% 未接充电
env=28.0C 21.0%RH
sd=mounted
heap=172435/138412 psram=6460180
```

- `wake`：本次启动的唤醒源，`cold` 冷启动 / `timer` 定时 / `key1`–`key3` 按键。
- `display`：显示任务状态，`starting` / `idle` / `busy` / `dead`。`dead` 表示它初始化失败已经退出，屏不会再刷新——看 `last` 和日志定位。
- `last`：最近一次刷屏结果，`ok` / `load-failed` / `no-image` / `fallback` / `factory`。
- `plugged`：TP4056 说正在充电。`usb`：USB 主机枚举上了。
- `sleep`：`off-powered` 插着电或连着电脑不睡 / `hold` 被 `awake` 钉住 / `waiting` 还在等空闲窗口 / `due` 条件已满足。
- `heap`：内部 RAM 的当前空闲 / 历史最低空闲，和 PSRAM 空闲。分配失败类问题先看这个。

返回里的 `queued` 表示命令已入队，不代表动作已经做完——一次整帧刷新要几十秒。

设备 IP 见串口日志里 `wifi: 已连上 ...` 那一行，也可以用 OTA 工具的探测结果。

## 睡眠

设备在电池供电、空闲 5 min 后自动进入深度睡眠，按键或定时器唤醒。接着充电器（正在充电或已充满）时不睡，普通插电调试和 OTA 不会被打断。USB 已枚举但充电状态仍是未接充电，只会出现在不供电的烧录线上，这是特例，一般不会遇到，此时也不自动睡。`sleep` 可以立即入睡，不看这两条。完整规则、唤醒源和电流预算见 [低功耗.md](低功耗.md)。
