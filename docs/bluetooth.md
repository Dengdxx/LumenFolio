# 蓝牙连接

Windows、Android 和微信小程序都可通过低功耗蓝牙直连相框。不需要 Wi-Fi，连接后仍可传图、浏览图库和升级固件。

## 连接相框

1. 确认相框和应用都支持蓝牙直连。旧固件可先用 [Wi-Fi OTA](ota.md) 升级，空白主板走[有线部署](firmware.md)。
2. 打开系统蓝牙并允许应用扫描。长按相框的 KEY3（重刷键）约两秒，白灯慢闪时相框在 60 秒内可被发现；相框深睡时也可按住 KEY3 唤醒并打开窗口。
3. 在应用连接页选 **蓝牙**；小程序选 **蓝牙连接**。只有一台相框在广播时会直接连接，多台时选择目标。系统提示配对时确认。

相框一次只接收一个蓝牙连接，连上后停止广播。窗口到期不会主动断开，但空闲连接也不会一直阻止相框深睡。要更换应用，先断开现有连接，再长按 KEY3。窗口到期后断线或相框已经深睡时，也需要重新开窗口。

通过蓝牙[升级固件](ota.md)时保持应用在前台、相框供电。待确认的新镜像会短暂恢复广播，以便原应用重连并确认。

## 传输边界

固件的 [NimBLE GATT 服务](../main/board_ble.cpp)要求加密，通过 Just Works 配对；它不核对 PIN，也不提供防中间人的身份认证。Windows 和 Android 可用蓝牙公开地址减 2 与设备报告的基 MAC `id` 核对是否连到同一台相框，这也不是密码学认证。

蓝牙请求通过相框本机回环进入同一套 HTTP 路由，和 Wi-Fi 共用帧校验、文件操作、SPI 队列和 OTA 回滚。应用内传图、图库和固件升级使用当前会话，**更换连接**会先关闭旧会话。蓝牙请求按顺序发送；仍可连接时，下个请求可重连，但不会自动重发已发出的写请求。Windows CLI 单独建立 Wi-Fi 会话。

## 易错点（务必遵守）

- **搜不到相框** → 深睡关闭射频、窗口到期，或其他应用／系统蓝牙已占用连接 → 如有占用先断开，无需遗忘配对；长按 KEY3 约两秒，再搜索。
- **提示连上了另一台相框** → 这次的 `id` 和 App 记住的不同 → 确认是不是换了设备。旧固件不报 `id`，App 不会拦截。
- **从已有构建目录编译时报 NimBLE 不可用** → 生成的 `sdkconfig` 仍关闭蓝牙 → 执行 `idf.py --preset release fullclean`，再用 Release preset 构建。Debug 使用对应的 `debug` preset。
- **Android 提示无法扫描** → Android 12 及以后需要「附近的设备」权限，Android 8–11 扫描需要位置权限和系统定位开关 → 在系统设置中打开对应权限后重试。
- **蓝牙传整帧或固件较慢** → 速度取决于双方协商的 ATT MTU 和连接间隔 → 保持在相框附近，等待 App 的传输进度。链路中断后，核对图库或 OTA 状态再决定是否重试。
