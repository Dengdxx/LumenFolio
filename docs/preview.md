# 六色预览

LumenFolio 桌面端在 Windows 上以一个 exe 提供图形界面和命令行。不带参数，或唯一参数是一张 PNG／JPEG 时，打开界面；`ota`、`frame`、`export`、选项和其他参数走命令行，未知命令退出码为 2，不开窗口。界面在 1200×1600 的六色面板上选构图、比较抖动。固件升级步骤见 [局域网 OTA](ota.md)。

## 代码边界

桌面端源码在 `app/pc/`，Go 模块名为 `lumenfolio`。界面和命令行共用能力，不共用窗口。两边都要调用的代码放在不引用 `gioui.org` 的包里；只服务于指针、字体、控件和布局的代码留在主包。

- `app/pc/panel`：取景、按取景框采样、六色抖动和帧编解码。编码压得更小时是 EPD2，否则是 EPD1。解码直接用相同的墨水近似色还原设备帧，保留设备保存的像素。墨水索引与固件帧缓冲的半字节一致。
- `app/pc/frame`：把一整帧 POST 到设备的 `/frame`。界面的「上传到相框」和命令行的 `frame` 都调用它。
- `app/pc/gallery`：读取 Flash artifacts 或 SD 卡中的帧清单和六色预览，供 Windows 和 Android 配套 App 共用。
- `app/pc/ota`：查询 `/ota/status`、上传应用镜像、等待重启并确认。Windows 和 Android 的「固件升级」以及命令行的 `ota` 子命令共用这个包。
- 主包（`ui.go`、`gallery_ui.go`、`ota_ui.go`、`gesture.go`、`send.go`）：窗口、字体、控件、布局、屏幕坐标、拖拽和应用层操作。`app.Main` 只在打开界面时由主 goroutine 调用，命令行路径不进入它。

这样分是因为 Gio 的事件循环会占住进程。共用包一旦引用 Gio，只跑命令行也会链进界面运行时。Go 也不允许在主包给 `panel.Crop` 增加方法，所以屏幕上的平移和旋转是主包函数，算完再调用 `Move`、`RotateAroundFrameCenter`、`Zoom`。

之后从界面或命令行加能力，先放进这种不引用 Gio 的包，再由两边各自调用。不要在 `ui.go` 里再写一套采样、抖动、编码或上传。

## 易错点（务必遵守）

- **新版工具传图被拒绝，或压缩图读不出来**：旧固件只认 EPD1。先升级支持 EPD2 的固件，再使用新版工具上传或重写开机图；新固件仍直接读取已有 EPD1。
- **上传返回 202 却没有换成新图**：202 只表示写入并请求刷新，压缩流由显示任务随后验证。损坏、截断、解压长度不符或 Adler32 错误的帧不会上屏；检查显示任务日志，再重新导出和上传。
- **浏览时提示固件暂不支持**：旧固件没有图片读取接口。按 [局域网 OTA](ota.md) 升级固件后重新打开「查看相框图片」。
- **纯白变黄、墨水颜色被替换**：原因是 Bayer／随机噪声把最近色与次近色的选中概率反用了。阈值必须随最近色色差减小而降低；精确命中某种墨水时保持原色。
- **透明 PNG 变黑或变暗**：`Color.RGBA()` 返回预乘 alpha 的颜色，直接忽略 alpha 会把透明区域变黑。采样必须先与白底合成，再做插值和抖动，与取景视图保持一致。
- **预览只显示左上角**：缩小裁剪区域并不等于缩小图片。必须用 `widget.Image` 的 `Contain` 同步缩放图像，保证完整构图可见。
- **模式标签能显示但点不动**：只画文字与背景不会注册点击区域。自绘标签仍须经过 `Clickable.Layout`，切换模式后请求重绘以同步选中高亮。
- **右键拖动不能旋转**：`gesture.Drag` 会过滤右键。画布直接接收指针事件，并捕获发起拖拽的指针 ID；其他指针和鼠标中键不能接管当前操作。
- **点击后图片跳动**：Windows 捕获鼠标后，首个拖拽事件坐标可能相对按下位置跳变。首个拖拽事件只重置基准，后续事件才累加相邻差值；取消或释放后停止拖拽。
- **读图不刷新或一直显示计算中**：后台读图结果入队后必须唤醒窗口；抖动结果遇到满队列时必须等待交付，不能直接丢弃。是否过期由 UI 事件循环按构图版本和算法判断。
- **重算预览时点击「打开图片」无反应**：文件选择和预览计算曾共用忙碌状态。两者各自维护状态，预览计算期间仍可打开图片。多次后台唤醒可能合并，窗口事件循环须处理完已就绪的结果。
- **取消文件选择后第一次点击丢失**：按钮忙碌时若停止读取 Gio 点击，下一帧会失去事件过滤器。仍须读取点击，只在忙碌时禁止执行动作；绘制前先应用已就绪的文件操作结果。

## 运行

需要 Windows 上的微软雅黑（`C:\Windows\Fonts\msyh.ttc`）。找不到时仍能打开，但中文会变成方框。

源码变化后先编译一次，之后直接跑生成的 exe：

```powershell
go -C app/pc build -o LumenFolio.exe .
.\app\pc\LumenFolio.exe
```

exe 不入库，源码没变就不要重新编译。不带参数打开空白界面；把一张 PNG／JPEG 路径作为唯一参数时，程序会在启动后直接打开它。读图成功、取消选择或读取失败都会主动更新界面，不需要移动鼠标触发。

## 取景

打开图片后，画布中央是一个固定的取景框，宽高比严格等于面板的 1200:1600。动的是背后的原图：

- 鼠标左键拖拽：平移
- 滚轮：以指针位置为锚点缩放
- 右键拖拽，或拖动框顶的把手：围绕框中心旋转；按住后移出画布仍可继续拖动
- 侧栏的 `-90°`、`+90°` 和「复位」：整数旋转或恢复初始构图
- 顶部「取景选取」「六色预览」标签和快捷按钮：切换视图

框外压暗。原图盖不住的地方填白，透明 PNG 也按白底合成。

## 抖动

切到「六色预览」后，程序先按取景框把原图采样成 1200×1600，再做抖动并等比缩小显示完整构图。抖动不在缩小后的预览图上做，否则颗粒和上屏不一致。

可选算法按界面顺序是：最近色、Floyd-Steinberg、Bayer 4×4、Bayer 8×8、随机噪声、Floyd-Steinberg（蛇形）、Atkinson、Sierra Lite、Burkes、Sierra Two-Row、Sierra、Stucki、Jarvis–Judice–Ninke、蓝噪声 64×64。列表超出侧栏时可以滚动。墨水是黑、白、黄、红、蓝、绿，索引与固件帧缓冲的半字节一致。Bayer、随机噪声和蓝噪声在输入像素精确命中墨水时保持该墨水。界面上的颜色只是这些墨水的 RGB 近似，不是面板的真实反射。

拖拽或滚轮停下来约 120 ms 后重新采样并抖动。旧版本任务的结果不会覆盖当前取景与算法的预览。

## 传到相框与导出

侧栏填相框地址后，「上传到相框」把**当前取景和当前抖动算法**编成一帧，POST 到 `http://<地址>:8080/frame`。整帧压缩后更小时用 EPD2，否则仍是 960012 字节的 EPD1；不改变抖动算法或任何像素。设备写入 artifacts 的上传槽并刷上屏，覆盖上一次传来的那张，不进 TF 卡，也不改开机画面。一次刷新约 35 秒，按钮返回时画面可能还在刷。

「导出帧文件」用同样的编码写到本地 `.bin`，不连接设备。命令行不带取景调整，按整图等比放进面板、居中、不旋转来编码：

```powershell
.\app\pc\LumenFolio.exe export 照片.png 画面.bin
.\app\pc\LumenFolio.exe --host 192.168.137.42 frame 照片.png
```

`--alg` 是抖动算法序号，与界面列表一致，从 0 起，默认 1（同向扫描的 Floyd-Steinberg）。新算法只追加在列表末尾，已有序号不变。导出的文件和 TF 卡上的帧是同一种格式，拷进卡的根目录后用翻页命令显示。

## 查看相框图片

在侧栏填写相框地址，点击「查看相框图片」。顶部可在「Flash artifacts」和「SD 卡」间切换。Flash 列出已有帧的开机槽和上传槽，SD 卡列出相框已扫描的根目录 `.bin` 帧文件。点击列表项可以预览设备保存的六色画面，操作只读取设备数据。点击「刷新」重读当前来源，点击「返回」继续本地取景。

## 固件升级

点击侧栏的「固件升级」，填写相框地址并选择已下载的 `LumenFolio.bin`。核对文件名与版本后点击「确认升级」，等待应用显示新固件已启动并确认。设备和电脑需位于同一可信局域网。 [局域网 OTA](ota.md)

## 帧格式与兼容性

两种格式都表示整幅 1200×1600，保留原来的六色码：`0` 黑、`1` 白、`2` 黄、`3` 红、`5` 蓝、`6` 绿。每字节存两个像素，偶数列占高半字节；像素按行排列，每行 600 字节。压缩只作用于文件和传输，不改变画质、显示驱动或现有双缓冲大小。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `EPD1` 或 `EPD2` |
| 4 | 8 | 小端 `uint16 x,y,w,h`，固定为 `0,0,1200,1600` |
| 12 | 4 | 仅 EPD2：小端 `uint32`，表示后续 zlib 载荷的字节数 |

EPD1 从偏移 12 起直接存 960000 字节像素，总长 960012。EPD2 从偏移 16 起存标准 zlib 流，包含 zlib 头和 Adler32；解压结果恰好是 960000 字节像素，不含 EPD1 帧头。编码器只有在 EPD2 的整个文件比 EPD1 更小时才选压缩，否则原样回退 EPD1。Go 与 Python 工具遵循同一布局，文件扩展名仍为 `.bin`。

固件的 `epd_frame` 组件供 Flash 资产和 TF 卡共用：验证尺寸、输入边界、完整流结束、无尾随压缩数据、Adler32 和固定输出长度后才绘制。解码复用已有两块 PSRAM 缓冲，额外只在堆上分配 miniz 状态，不再申请整帧，也不把解压状态放在任务栈上。Flash 的开机槽与上传槽仍各为 1 MB；文件缩小不自动增加槽数，上传仍擦除整个槽。资产帧的完整读取与擦除、写入互斥，避免下一次上传覆盖正在读取的上一帧。

新固件可直接读取已有 EPD1；旧固件不能读取 EPD2，必须先升级固件，再上传新帧或烧录压缩开机图。应用 OTA 不改写已有资产，设备上的旧图不会被自动转换。

## 回归测试

```bash
go -C app/pc test -p=1 ./...
```

```bash
go -C app/pc vet -p=1 ./...
```

取景、抖动和帧编码的测试在 `app/pc/panel`，传图在 `app/pc/frame`，固件上传在 `app/pc/ota`，指针手势和导出命令在主包。上面的 `./...` 会一起跑，覆盖取景变换、透明度与白底合成、六色抖动、EPD2 无损还原与 EPD1 回退、非法帧拒绝、实际传输长度、导出字节数、鼠标事件路由、后台结果交付和完整预览显示。并发交付使用 `testing/synctest` 控制任务时序，不依赖真实时间休眠。离屏绘制测试覆盖普通窗口、不同留边和高 DPI；无法创建 GPU 后端时会标记跳过，不能把跳过视为已验证显示效果。

Python 产帧工具的六色色码、高低半字节顺序、原始帧回退与尺寸边界：

```bash
python -I -m unittest discover -s tools -p test_frame_format.py -v
```

固件解码器的独立 ESP32S3 测试工程：

```bash
idf.py -C components/epd_frame/test_apps build
```

这个命令只编译测试程序。测试覆盖 EPD1／EPD2 还原、固定槽边界、错误帧头、Adler32 损坏、截断、尾随压缩数据、输出少一字节和解压膨胀；执行 ROM 解压测试需要在带 8 MB PSRAM 的测试板上运行该独立固件。它不是相框固件的开机自检，不要通过相框 OTA 上传测试镜像。
