# FrameFolio 7 寸相框 · 灯语设计

> 本文只做提取、归并和冲突标注，不新增产品规则。
> 标注「补充建议」的内容是实现时需要自行确定、原文未定义的参数。

## 1. 设计原则

1. **单一归属**：WS2812B 由独立的 LED 状态机独占驱动，业务模块（BLE、Wi-Fi、EPD、充电、TF）只发布事件，不直接操作灯。
2. **队列有序 + 持续状态双层**：一次性灯语进入有顺序保证的事件队列；等待、充电、传输、刷新等持续性灯语作为状态层存在。
3. **一次唤醒的固定顺序**：异常（若有）→ 电量 → 任务灯语。
4. **不阻塞**：ADC 采样函数不得直接点灯，只能把电量事件入队，避免阻塞 BLE、Wi-Fi 或 EPD 任务。
5. **灯语可中断，任务不可中断**：高优先级灯语只抢占显示，不打断正在写文件、刷新屏幕或传输的任务。

## 2. 硬件与职责边界

| 信号 | GPIO | 用途 |
|---|---:|---|
| `RGB` | GPIO14 | WS2812B 单线数据输入 |
| `POWER_CHG` | GPIO39 | TP4056 `CHG`，充电中判据之一 |
| `POWER_FULL` | GPIO38 | TP4056 `STDBY`，充满/待机判据之一 |
| `ADC_BAT` | GPIO1 | 电池电压采样，经外部分压/控制网络 |
| `ADC_CTL` | GPIO2 | 电池检测/ADC 分压控制，按电路时序开关 |

灯语模块只依赖 `board_led_set(r, g, b)` 这一出口；GPIO 编号集中在板级配置中，业务代码不得出现。

## 3. 结构模型

### 3.1 事件队列（一次性灯语）

一次唤醒内按优先级出队，逐项播放，不叠加：

```text
异常/故障（红色快闪十次）
  → 电量前置事件（渐变常亮一次）
  → 任务事件（连接成功 / 传输完成 / 刷新完成 / 挂载成功）
```

同优先级事件按发生顺序 FIFO 播放。绿色「完成」类事件需逐项播放，不能与连接灯语同时叠加。

### 3.2 持续状态层

同一时刻只有一个持续状态可见：

```text
Pair 等待白色慢闪
  > 充电时按电量渐变的常亮
  > 空闲待机（无色）
```

活动灯语（BLE 传图蓝色快闪、Wi-Fi 传图青色快闪、EPD 刷新黄色慢闪）在发生期间覆盖等待/充电/空闲状态；事件结束后若 Pair 窗口仍有效，恢复白色等待慢闪。

### 3.3 归一化仲裁规则（补充建议）

任一时刻的显示判定：

1. 事件队列非空 → 播放当前事件；
2. 否则存在活动任务 → 播放对应持续灯语（蓝快闪 / 青快闪 / 黄慢闪）；
3. 否则 Pair 窗口有效 → 白色慢闪；
4. 否则充电中 → 电量渐变常亮；
5. 否则无色。

异常事件到达时暂停「可暂停」的持续灯语，红十闪结束后播放一次电量提示，再恢复被暂停的持续灯语或继续播放后续事件。文件传输和 EPD 刷新本身不因灯语抢占而暂停。

## 4. 灯语全集

| 编号 | 灯效 | 类型 | 含义 | 触发 | 结束条件 |
|---|---|---|---|---|---|
| L1 | 白色慢闪 | 持续 | Pair 唤醒窗口，等待 BLE 连接；已配置 Wi-Fi 时同时等待 Wi-Fi STA | Pair 唤醒且前置队列播完 | Pair 窗口到期，或被更高优先级灯语覆盖；窗口到期不关闭已建立链路 |
| L2 | 绿-红渐变常亮 | 持续 | 充电状态显示，颜色按采样电量映射；充电/充满的精确状态由 `CHG`/`STDBY` 判定并记入日志 | 判定为充电中 | 无更高优先级 Pair/任务灯语时显示 |
| L3 | 蓝色快闪 | 持续 | BLE 传输图片 | BLE 文件传输开始 | 传输结束 |
| L4 | 青色快闪 | 持续 | Wi-Fi 传输图片 | Wi-Fi 下载开始 | 下载结束 |
| L5 | 黄色慢闪 | 持续 | EPD 正在 BUSY/刷新 | 刷新开始 | `BUSY` 结束 |
| L6 | 黄色短闪一次（第 6 节表格写作「黄色慢闪一次」） | 一次 | 本机切图/轮播无有效图片，未切换 | 无有效图片、TF 不存在或挂载失败 | 播放一次后结束，随后进入休眠收尾 |
| L7 | 蓝色慢闪一次 | 一次 | BLE 连接成功 | BLE 建立连接 | 播放一次 |
| L8 | 青色慢闪一次 | 一次 | Wi-Fi 连接成功 | STA 连接路由器成功 | 播放一次 |
| L9 | 绿色慢闪一次 | 一次 | EPD 更新完成、传输完成或 TF 挂载成功 | 对应任务正常结束 | 播放一次，逐项播放不叠加 |
| L10 | 红色快闪十次 | 一次 | 任意异常/故障 | 见第 7 节 | 播放十次 |
| L11 | 无色 | 持续 | 空闲待机 | 无活动、无充电、无 Pair 窗口 | 出现更高优先级灯语 |

说明：

- 「快闪 / 慢闪 / 短闪」的具体频率、占空比和亮度原文未定义，见第 9 节。
- L6 在原文中同时存在「黄色短闪一次」和「黄色慢闪一次」两种写法，需统一。
- 第 5.4 节把 Wi-Fi 传输灯语写作「蓝色/绿色传输灯语」，第 6 节表格定义为青色；以第 6 节为准。

## 5. 一次唤醒的固定时序

电量采样是所有唤醒路径的共同前置步骤，包括 Pair、定时唤醒、上翻/下翻本机切图、TF 检测和其他 GPIO 唤醒：

```text
唤醒
→ 电源稳定等待 / 打开 ADC 分压（ADC_CTL）
→ 读取 ADC_BAT，并读取 TP4056 CHG/STDBY
→ ADC 校准、滤波、电量映射
→ 充电状态交叉判断
→ 入队电量灯语
→ 执行 Pair、BLE、Wi-Fi、EPD、自检或本机切图任务
```

排布规则：

1. 无异常：先播放一次电量灯语，再播放任务灯语。
2. 有异常：红色快闪十次 → 电量提示一次 → 任务灯语。
3. 本次任务没有任务灯语时，只保留电量灯语，不为显示而强行创建任务灯语。
4. 电量灯语必须入队，不能由采样函数同步阻塞播放。
5. 传输类任务先显示一次电量灯语，再进入蓝色/青色传输灯语；传输期间不重复覆盖电量灯语，除非发生新的唤醒或明确的低电量事件。

电量颜色为绿-红线性渐变：电量高偏绿，电量低偏红。满电电压、低电阈值、临界阈值、分压误差和颜色映射由实测标定。日志应保留原始电压、滤波电压、估算百分比和最终颜色值，不能仅凭颜色反推精确电量。

## 6. 分场景灯语编排

### 6.1 Pair 唤醒（未配置 Wi-Fi，BLE-only）

```text
前置：异常?（红十闪）→ 电量一次
白色慢闪（Pair 主动连接窗口 0–60 秒）
BLE 连接成功 → 蓝色慢闪一次 → 窗口内恢复白色慢闪
BLE 传图 → 蓝色快闪
EPD 刷新 → 黄色慢闪
刷新完成 → 绿色慢闪一次
60 秒到期 → 停止白色等待；已建立连接与传输的灯语继续
结束 → 统一休眠收尾
```

### 6.2 Pair 唤醒（已配置 Wi-Fi，BLE+Wi-Fi）

```text
前置：异常?（红十闪）→ 电量一次
白色慢闪（BLE 广播与 Wi-Fi STA 并行，各自最多 60 秒）
BLE 成功 → 蓝色慢闪一次
Wi-Fi 成功 → 青色慢闪一次
任一链路成功只播对应事件，不关闭另一条链路
Wi-Fi 心跳返回 download_film → 青色快闪 → 黄色慢闪 → 绿色慢闪一次
心跳空命令 → 无任务灯语，不报错
BLE 传图 → 蓝色快闪（与 Wi-Fi 任务由统一队列仲裁）
60 秒到期只停止尚未建立的连接尝试
```

### 6.3 上翻/下翻按键唤醒（本机切图）

```text
前置：异常?（红十闪）→ 电量一次
无有效图片 → 黄色短闪一次，不刷新
有有效图片 → 黄色慢闪（EPD BUSY）→ 绿色慢闪一次
不启动 BLE/Wi-Fi，因此不出现连接灯语
结束 → 统一休眠收尾
```

### 6.4 RTC 自动轮播（默认 30 分钟）

与 6.3 相同：黄色短闪一次（无图）或黄色慢闪 → 绿色慢闪一次（有图），全程不出现连接/传输灯语。

### 6.5 基础模式定时自检（自动唤醒到期，未配置 Wi-Fi）

```text
前置：异常?（红十闪）→ 电量一次
有有效图片 → 黄色慢闪（维护刷新）→ 绿色慢闪一次
无有效图片 → 执行清残影/白屏维护刷新 → 黄色慢闪 → 绿色慢闪一次
（这里与切图/轮播不同：自检即使无图也会刷新，因此不播黄色短闪）
EPD 失败/TF 失败 → 红色快闪十次
不启动 BLE/Wi-Fi，无连接灯语
```

### 6.6 Wi-Fi 拓展模式定时云同步

```text
前置：异常?（红十闪）→ 电量一次
Wi-Fi 连接成功 → 青色慢闪一次
心跳空命令 → 无任务灯语
download_film → 青色快闪（下载）→ 黄色慢闪（刷新）→ 绿色慢闪一次
图片 204 → 无任务，不记为错误，不播红灯
网络/校验/写卡失败 → 红色快闪十次
结束 → 断开 Wi-Fi → 统一休眠收尾
```

### 6.7 小程序 0x3C 主动下载

心跳后无条件执行一次用户主动 GET：`200` 走上下载流程，`204` 为无任务，失败红十闪。

### 6.8 配置变更

原文没有为配置写入定义专用灯语。写入失败按通用异常处理（红十闪并记录错误码）；写入成功不额外点灯，除非与 TF 挂载成功等既有 L9 事件重合。

### 6.9 休眠收尾

- 停止业务灯语，进入无色。
- 允许深睡：关闭射频与外设后深睡；深睡期间 LED 是否保持充电指示原文未定义（见风险 11.6）。
- 禁止深睡：BLE 持续可连接广播待命，空闲时无色，充电时显示渐变常亮。

## 7. 异常与充电

### 7.1 输入与判定

充电判断同时读取四路信号：

1. `POWER_CHG`：TP4056 `CHG`，表示充电中；
2. `POWER_FULL`：TP4056 `STDBY`，表示充满/待机；
3. `ADC_BAT`：电池电压；
4. `ADC_CTL`：电池检测或 ADC 分压控制状态。

`CHG`/`STDBY` 与电池电压长期矛盾、欠压、ADC 越界均属异常。极性、分压比、稳定时间和去抖时间需按原理图与实测确定。

### 7.2 异常范围

包括但不限于：

- ADC/欠压异常、充电状态不匹配；
- TF 无法挂载、读写失败；
- EPD 初始化失败、`BUSY` 超时；
- BLE/Wi-Fi 连接或传输失败；
- 文件格式或校验错误；
- OTA 校验或写入失败。

每种异常有独立错误码和上下文日志，但通用灯语统一为**红色快闪十次**。不能把最高优先级错误灯语限制为充电错误。

### 7.3 ADC 采样失败

ADC 采样失败本身是异常：

1. 先记录具体错误，不得用无效值计算电量颜色；
2. 红色快闪十次；
3. 显示一次预定义的「电量不可读」提示（红色短脉冲或沿用最后一次有效电量颜色，实机阶段确定）；
4. 随后继续执行可安全任务，或按故障策略退出。

### 7.4 异常期间的顺序

```text
异常事件（最高优先级）
→ 红色快闪十次
→ 电量提示一次
→ 恢复被暂停的持续任务灯语 / 继续后续任务事件
```

异常处理只抢占灯语，不强制中断正在写文件或刷新屏幕的任务。

## 8. 与其他优先级的对应关系

任务冲突优先级（第 12.2 节）：

```text
异常处理/故障记录
  > 正在进行的 OTA、BLE/Wi-Fi 文件传输、EPD BUSY 刷新
  > 定时唤醒自检/服务器 GET
  > RTC 自动轮播
  > 普通空闲和充电常亮
```

灯语显示与此对应：高优先级任务可以延后低优先级任务，因此其灯语也优先显示；但「高优先级」不表示强行中断正在写文件或刷新屏幕的任务。

## 10. 实现落点（补充建议）

灯语由独立模块独占 WS2812，`board_led_set()` 只是出口，业务侧只调用事件/状态接口：

```c
typedef enum {
    LED_EV_ANOMALY,          // 红色快闪十次
    LED_EV_BATTERY,          // 电量渐变色一次
    LED_EV_BLE_CONNECTED,    // 蓝色慢闪一次
    LED_EV_WIFI_CONNECTED,   // 青色慢闪一次
    LED_EV_EPD_DONE,         // 绿色慢闪一次
    LED_EV_TF_MOUNTED,       // 绿色慢闪一次
    LED_EV_NO_IMAGE,         // 黄色短闪一次（待统一定义）
} led_event_t;

typedef enum {
    LED_STATE_IDLE,          // 无色
    LED_STATE_PAIR_WAIT,     // 白色慢闪
    LED_STATE_CHARGING,      // 电量渐变常亮
    LED_STATE_BLE_XFER,      // 蓝色快闪
    LED_STATE_WIFI_XFER,     // 青色快闪
    LED_STATE_EPD_BUSY,      // 黄色慢闪
} led_state_t;

esp_err_t led_fsm_init(void);
esp_err_t led_event_post(led_event_t ev, uint8_t percent); // 一次性事件，非阻塞
esp_err_t led_state_set(led_state_t st, bool on);          // 持续状态开关
```

实现要点：

- 用独立任务或 `esp_timer` 驱动闪烁节拍，禁止在业务任务里 `vTaskDelay` 播放灯语。
- 事件队列按「异常 → 电量 → 任务」的优先级出队；同优先级 FIFO。
- 持续状态用位图或计数管理，支持多个任务同时声明、按优先级取最高。
- 深睡前先停止灯语任务并熄灭 LED（是否保留充电指示待第 9 节确定）。
- 颜色、周期、亮度全部做成集中常量，便于实机标定，不散落在业务代码中。
