# 低功耗与深度睡眠

面板是双稳态的，断电也保画面，所以设备绝大部分时间可以整片睡过去。这里写清楚什么时候睡、谁能唤醒、睡前做了什么，以及本板做不到的地方。

## 睡眠策略

| 条件 | 行为 |
| --- | --- |
| 电池供电，空闲 30 s | 进入深度睡眠 |
| 接着充电器（正在充电或已充满） | 不自动睡 |
| 电脑连着 USB（串口枚举上了） | 不自动睡。带电的线上一行已经盖住；单独走到这一行，是不供电的烧录线，一般不会遇到 |
| 收到 `awake` 命令 | 本次开机都不自动睡 |
| 正在写 OTA 固件 | 不自动睡，等这次空闲过去 |
| 收到 `sleep` 命令 | 立即睡，不看上面几条 |

插电不睡是有意的：睡了就收不到 OTA，而插着电通常说明设备在人手边。参数在 `main/main.cpp` 的 `kIdleSleepMs`。

一般情况看 TP4056：充电器或普通带 VBUS 的 USB 线接上后，正在充电或已充满就不自动睡。USB-SERIAL-JTAG 枚举到主机是额外一条，只为台面特例：现在这根烧录线只接了 D+/D-、不供电，TP4056 看不到输入，充电状态会一直是未接充电，电池也在放电。这种接线一般不会遇到。

睡眠决定由独立的电源守护任务（`power_guard_task`）每秒看一次，**不挂在显示任务上**：显示初始化失败或者卡在刷屏里，设备照样要能睡着。

## 唤醒源

| 源 | 条件 |
| --- | --- |
| 按键 | KEY1/KEY2/KEY3 任意一个被拉低（EXT1，低有效） |
| 定时器 | 每 600 s（`framefolio::board_sleep::kTimerWakeSeconds`） |

**插拔 USB 唤不醒设备。** 充电状态接在 GPIO38/39 上，这两个脚不属于 RTC IO（S3 只有 GPIO0–21 是），做不了唤醒源。睡眠中插上充电器，要等下一次定时唤醒才发现。

唤醒的那一下按键会当成一次操作补投给显示任务：按 KEY2 唤醒会直接翻到下一张，不用按第二次。没有"只唤醒不动作"的按键。

## 定时唤醒做什么

每次定时唤醒先采一次电池：

- 发现接着充电器：按正常开机走（起 Wi-Fi、起 HTTP），之后不会再自动睡。
- 没接充电器：什么都不初始化，直接回睡。这条路径不开 3V3_EXT，也不给面板上电。
- 没接充电器且攒够 144 次（24 h）：补刷一帧当前画面，防残影。

## 睡前动作

顺序不能换，`main/main.cpp` 的 `enter_deep_sleep()` 是唯一入口：

1. `led_fsm_suspend()`：挂起灯语任务并写一帧黑色，睡着时灯是灭的。
2. `board_sd_unmount()`：FAT 元数据落盘，卡退出传输态。
3. `epdParkBus()`：面板控制脚全部浮空。
4. `framefolio::board_sleep::enter()`：拉低并保持 POWER_CTL / ADC_CTL / LED 数据脚，配置 EXT1 与定时器，`esp_deep_sleep_start()`。

当前显示到第几张存在 RTC 内存里（`s_frame_index`），唤醒后接着上一张，不会跳回第一张。

## 手动入口

```bash
# 串口：输入 sleep 后回车
sleep
awake

# HTTP
curl 'http://<设备IP>:8080/console?cmd=sleep'
curl 'http://<设备IP>:8080/console?cmd=awake'
```

`sleep` 不看充电器、USB 枚举和 OTA 状态，适合在台面上验证睡眠电流。`awake` 把设备钉在醒着的状态直到复位或下一次 `sleep`。电池供电、又要长时间醒着时用；接着充电器时本来就不会自动睡。

## 电流预算

本板做不到芯片手册上那种 10 µA 量级，因为几条常电支路断不掉：

| 支路 | 待机电流 | 能否断开 |
| --- | --- | --- |
| ESP32-S3 深睡 | 约 10 µA | — |
| WS2812（VDD 接 3V3_MCU） | 0.3–1 mA | 不能，写完黑色后仍有静态电流 |
| TF 卡（VDD 接 3V3_MCU） | 0.1–0.5 mA | 不能，卸载只能让它退出传输态 |
| SY8089（VBAT → 3V3_MCU） | 几十 µA | 不能，MCU 自己在这条轨上 |

合计约 1 mA。1000 mAh 电池大约能撑一个月，再往下要靠改硬件（给 LED 和卡加负载开关）。

## 易错点

- **睡眠不能挂在显示任务上**：上板遇到过显示任务在 `xQueueCreateSet` 失败后直接 `vTaskDelete` 自己退出，此后没人再判断睡眠，设备在电池上一直醒着耗到没电。现在睡眠由独立的电源守护任务负责，显示任务只报告自己 `busy` 与否。
- **POWER_CTL 没有下拉电阻**：深睡后 GPIO40 变高阻，SY8089 的 EN 浮空，3V3_EXT 可能自己又起来。必须 `gpio_hold_en()` 把低电平锁住，并配合 `gpio_deep_sleep_hold_en()`。
- **ADC_CTL 同理**：Q7 栅极浮空可能导通，220k/110k 分压支路会一直漏电。
- **按住不放的键不能进唤醒掩码**：进掩码会让睡眠立刻结束，等于睡不下去。`framefolio::board_sleep::enter()` 只收当前是高电平的键。
- **唤醒后先 `release_holds()`**：数字脚的保持位随复位清掉，但 RTC 脚的会留下来（ADC_CTL、LED 数据脚都在 0–21 内），不主动解开会停在被锁死的电平上。
- **定时唤醒不要开 3V3_EXT**：面板每次上电都是一次冲击，而这条路径根本不刷屏。3V3_EXT 的开启因此挪到了显示任务里（`board_power_rail_on()`）。
- **睡前必须 `epdParkBus()`**：控制脚还拉着高电平时切掉 3V3_EXT，电流会经面板输入的 ESD 二极管倒灌进已经关断的电源轨。

## 已知限制

- 睡眠中无法 OTA：设备不在网上。要么按一下键，要么等下一次定时唤醒（最多 10 分钟）。
- 深睡时 USB 外设已断电，主机看不到串口，也就烧不进去。按一下 RESET（SW3）或任意按键让设备跑起来再烧；接着 USB 时设备不会自动睡，烧完可以正常调试。
