# 低功耗与深度睡眠

电子纸无需持续供电即可保留画面。相框空闲时会关闭射频和外设电源，进入深度睡眠。

## 睡眠策略

| 条件 | 行为 |
| --- | --- |
| 条件 | 行为 |
| --- | --- |
| 电池供电，空闲 5 分钟 | 无下列阻止条件时进入深睡 |
| TP4056 报告正在充电或已充满，或 USB 串口已枚举 | 不自动睡，便于调试和 OTA |
| 收到 `awake` 命令 | 本次开机不自动睡 |
| 显示任务忙、帧读写请求进行中，或 OTA 不在 `idle` | 暂缓自动睡眠 |
| 按住 KEY3，或 BLE 最近 60 秒内开窗、连接或通信 | 暂缓自动睡眠 |
| 收到 `sleep` 命令 | 守护任务下次检查时强制入睡，不看其他条件 |

空闲计时和检查在 [`power_guard_task`](../main/main.cpp)。它每秒检查一次，不依赖显示任务继续运行；但显示状态卡在 `busy` 时仍会延迟自动睡眠。

USB 枚举是独立判据，覆盖只有数据线、没有 VBUS 的烧录接线。周期电池采样失败时保留上一次充电状态；没有成功采样时不会仅凭插线判断在充电。

## 唤醒源

| 源 | 条件 |
| --- | --- |
| 按键 | 已加入 EXT1 唤醒掩码的 KEY1、KEY2 或 KEY3 被拉低（入睡时仍按住的键不加入） |
| 定时器 | 每 600 s（`lumenfolio::board_sleep::kTimerWakeSeconds`） |

**插拔 USB 唤不醒设备。** 充电状态接在 GPIO38/39 上，这两个脚不属于 RTC IO（S3 只有 GPIO0–21 是），做不了唤醒源。睡眠中插上充电器，要等下一次定时唤醒才发现。

短按唤醒会补投一次对应的显示操作，按 KEY2 会直接翻到下一张。长按 KEY3 约两秒会唤醒相框并打开 [蓝牙连接窗口](bluetooth.md)。

## 定时唤醒做什么

每次定时唤醒先采一次电池：

- 发现接着充电器：按正常开机走（起 Wi-Fi、起 HTTP），之后不会再自动睡。
- 未检测到充电（含采样失败）：尚未到补刷次数时立即回睡，不启用 3V3_EXT，也不给面板上电。
- 未检测到充电且累计 144 次（连续深睡时约 24 小时）：启动显示任务补刷，防残影。补刷走默认来源，不保证仍是深睡前通过 App 选中的画面。

## 睡前动作

正常进入深睡走 `enter_deep_sleep()`，按下面顺序停外设。定时唤醒后立即回睡的分支没有启动这些外设，直接调用 `board_sleep::enter()`。

1. `board_ble_suspend()`：结束蓝牙通信，关闭 GATT 和回环套接字，停止控制器。
2. `led_fsm_suspend()`：挂起灯语任务并写一帧黑色，睡着时灯是灭的。
3. `board_sd_unmount()`：FAT 元数据落盘，卡退出传输态。
4. `epdParkBus()`：面板控制脚全部浮空。
5. `lumenfolio::board_sleep::enter()`：拉低并保持 POWER_CTL / ADC_CTL / LED 数据脚，配置 EXT1 与定时器，`esp_deep_sleep_start()`。

SD 卡翻页序号保存在 RTC 内存（`s_frame_index`）里，深睡唤醒后继续使用。通过 App 点选的来源只在本次开机内有效。

## 手动入口

通过[串口或 HTTP 控制台](控制接口.md#控制台)执行 `sleep` 或 `awake`。`sleep` 跳过供电和忙碌检查，适合测睡眠电流；不要在传图或 OTA 期间使用。`awake` 仅在本次开机阻止自动入睡，不会唤醒已深睡的设备。

## 电流预算

本板做不到芯片手册上那种 10 µA 量级，因为几条常电支路断不掉：

| 支路 | 待机电流 | 能否断开 |
| --- | --- | --- |
| ESP32-S3 深睡 | 约 10 µA | — |
| WS2812（VDD 接 3V3_MCU） | 0.3–1 mA | 不能，写完黑色后仍有静态电流 |
| TF 卡（VDD 接 3V3_MCU） | 0.1–0.5 mA | 不能，卸载只能让它退出传输态 |
| SY8089（VBAT → 3V3_MCU） | 几十 µA | 不能，MCU 自己在这条轨上 |

合计是约 1 mA 的估算，不是续航实测。实际续航还受唤醒、Wi-Fi、刷屏和电池容量影响。要显著降低静态电流，需要给常电的 LED 和卡加负载开关。

## 易错点（务必遵守）

- **睡眠不能挂在显示任务上**：上板遇到过显示任务在 `xQueueCreateSet` 失败后直接 `vTaskDelete` 自己退出，此后没人再判断睡眠，设备在电池上一直醒着耗到没电。现在睡眠由独立的电源守护任务负责，显示任务只报告自己 `busy` 与否。
- **POWER_CTL 没有下拉电阻**：深睡后 GPIO40 变高阻，SY8089 的 EN 浮空，3V3_EXT 可能自己又起来。必须 `gpio_hold_en()` 把低电平锁住，并配合 `gpio_deep_sleep_hold_en()`。
- **ADC_CTL 同理**：Q7 栅极浮空可能导通，220k/110k 分压支路会一直漏电。
- **按住不放的键不能进唤醒掩码**：进掩码会让睡眠立刻结束，等于睡不下去。`lumenfolio::board_sleep::enter()` 只收当前是高电平的键。
- **唤醒后先 `release_holds()`**：数字脚的保持位随复位清掉，但 RTC 脚的会留下来（ADC_CTL、LED 数据脚都在 0–21 内），不主动解开会停在被锁死的电平上。
- **定时唤醒不要开 3V3_EXT**：面板每次上电都是一次冲击，而这条路径根本不刷屏。3V3_EXT 的开启因此挪到了显示任务里（`board_power_rail_on()`）。
- **睡前必须 `epdParkBus()`**：控制脚还拉着高电平时切掉 3V3_EXT，电流会经面板输入的 ESD 二极管倒灌进已经关断的电源轨。

## 已知限制

- 深睡时 Wi-Fi 和蓝牙射频均关闭。按键唤醒后可以进行无线操作。相框插着充电器时，也可以等待下一次定时唤醒（最多 10 分钟）。
- 深睡时 USB 外设已断电，主机看不到串口，也就烧不进去。按一下 RESET（SW3）或任意按键让设备跑起来再烧；接着 USB 时设备不会自动睡，烧完可以正常调试。
